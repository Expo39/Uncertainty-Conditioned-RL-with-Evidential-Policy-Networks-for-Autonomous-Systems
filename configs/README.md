# configs/

YAML configuration files for all experiment parameters. **No hyperparameters are hardcoded in source** -everything is config-driven.

## Files

| File | Purpose |
|------|---------|
| `train_config.yaml` | Shared base config: PPO hyperparameters, environment settings (town, max\_steps), ROS 2 covariance subscription, sensor suite selection (`suite_a`), parking lot scenario settings (floor plans, bay occupancy, cone spacing, NPC counts), network architecture, evidential settings, training schedule |
| `eval_config.yaml` | Evaluation condition sweep: 7 performance conditions (ClearNoon / HardRainNoon only - fog not rendered on FlatPlane), 2 OOD conditions (`irregular_a` floor plan), and 1 worst-case safety handoff condition. Episode counts, success criteria thresholds, output settings. |
| `ros2_config.yaml` | ROS 2 node parameters: CARLA bridge topic names, robot\_localisation EKF settings (frequency, 2D mode, odom/imu fusion configs), covariance extraction node topics, QoS settings |

## Subdirectories

### `baselines/`

Override-only configs for the 2x2 ablation study. Each file contains only the keys that differ from `train_config.yaml`. The orchestration script (`scripts/run_experiment.py`) deep-merges each onto `train_config.yaml` at runtime.

| File | Observation | Policy | Notes |
|------|-------------|--------|-------|
| `vanilla_ppo.yaml` | 12-dim (pose + target + obstacle) | Standard | `include_covariance: false`, `policy_type: "standard"` |
| `input_uncertainty.yaml` | 21-dim (full) | Standard | `include_covariance: true`, `policy_type: "standard"` |
| `output_uncertainty.yaml` | 12-dim (pose + target + obstacle) | Evidential | `include_covariance: false`, `policy_type: "evidential"` |
| `full_method.yaml` | 21-dim (full) | Evidential | `include_covariance: true`, `policy_type: "evidential"` - main contribution |

### `layouts/`

Pre-computed parking lot geometry YAMLs generated by `make generate-layouts` (no CARLA needed). **Do not edit manually** -re-run `make generate-layouts` after updating origins.

| File | Floor plan | Training / OOD |
|------|-----------|----------------|
| `rectangle.yaml` | Standard rectangle, 60x45 m | Training |
| `trapezoid.yaml` | Trapezoid, wider at entrance (front=48, rear=30, depth=44 m) | Training |
| `irregular_a.yaml` | Nine-sided irregular polygon (~80x50 m), diagonal top wall and bottom notch | OOD only |

Each layout YAML contains: `corners` (perimeter polygon), `bays` (15 bay definitions with positions, dimensions, `always_empty` flags), `spawn_transform` (ego start pose), `patrol_waypoints`, and `pedestrian_zones`. Consumed by `CARLAParkingEnv._load_floor_plan()`.

Lot origins are pre-set for the FlatPlane map. Use `make docker-inspect LAYOUT=<name>` to verify placement visually. If you move a lot, update `origin.x/y` and re-run `make generate-layouts`.

## Convention

- All consuming code uses `.get(key, default)` so configs are backwards-compatible.
- Units are commented inline in each YAML.
- New parameters must be added to the relevant YAML with sensible defaults before use in code.
- Structural constants (dimensions, thresholds) live in `uncertainty_rl/utils/constants.py`, not here.
