# configs/

YAML configuration files for all experiment parameters. **No hyperparameters are hardcoded in source** -everything is config-driven.

## Files

| File | Purpose |
|------|---------|
| `carla/env_config.yaml` | CARLA environment settings: connection (`carla_host`, `carla_port`, `town`), simulation (`max_steps`, `carla_timestep`), ROS 2 covariance subscription, sensor suites (`carla_sensors.*`), parking lot scenarios (floor plans, bay occupancy, cone spacing, NPC counts), sensor suite selection, observation flags. Consumed by `CARLAParkingEnv` and all scripts that interact with CARLA. |
| `train_config.yaml` | RL training settings: PPO hyperparameters, network architecture, evidential settings (`lambda_reg`, `lambda_reg_warmup_steps`, `use_uncertainty_conditioning`), training schedule, logging and checkpointing. Consumed by `train_ppo.py`. **Modified by Optuna after tuning completes** (with `.bak` backup created). |
| `eval_config.yaml` | Evaluation condition sweep: 7 performance conditions (ClearNoon / HardRainNoon only - fog not rendered on FlatPlane), 2 OOD conditions, and 1 worst-case safety handoff condition. Episode counts, success criteria thresholds, output settings. |
| `ros2_config.yaml` | ROS 2 node parameters: CARLA bridge topic names, robot\_localisation EKF settings (frequency, 2D mode, odom/imu fusion configs), covariance extraction node topics, QoS settings |

## Subdirectories

### `baselines/`

Override-only configs for the 2x2 ablation study. Each file contains only the keys that differ from `train_config.yaml`. The orchestration script (`scripts/run_experiment.py`) deep-merges each onto `train_config.yaml` at runtime.

| File | Observation | Policy | Notes |
|------|-------------|--------|-------|
| `vanilla_ppo.yaml` | 11-dim (pose + target + obstacle) | Standard | `include_covariance: false`, `policy_type: "standard"` |
| `input_uncertainty.yaml` | 20-dim (full) | Standard | `include_covariance: true`, `policy_type: "standard"` |
| `output_uncertainty.yaml` | 11-dim (pose + target + obstacle) | Evidential | `include_covariance: false`, `policy_type: "evidential"` |
| `full_method.yaml` | 20-dim (full) | Evidential | `include_covariance: true`, `policy_type: "evidential"` - main contribution |

### `carla/`

CARLA-specific config and assets:

- `env_config.yaml` -- all CARLA environment and sensor settings (connection, sensor noise, parking scenarios, observation flags). Loaded by all scripts that interact with CARLA.
- `OpenDriveMap.bin` -- pre-built pedestrian navigation mesh for the FlatPlane OpenDRIVE world. Pre-built because CARLA segfaults during nav mesh generation on headless GPU setups. See `carla/README.md` for regeneration instructions.

### `cartographer/`

Google Cartographer Lua configs (4 files). Selected automatically by the launch file based on `SENSOR_SUITE` and `CARTOGRAPHER_MODE`:

| Config | Suite | Mode |
|--------|-------|------|
| `cartographer_config.lua` | A (2D LiDAR) | SLAM |
| `cartographer_config_loc.lua` | A (2D LiDAR) | Pure localisation |
| `cartographer_config_3d.lua` | B/C (3D LiDAR) | SLAM |
| `cartographer_config_3d_loc.lua` | B/C (3D LiDAR) | Pure localisation |

### `layouts/`

Pre-computed parking lot geometry YAMLs generated by `make generate-layouts` (no CARLA needed). **Do not edit manually** -- re-run `make generate-layouts` after updating origins.

| File | Floor plan | Training / OOD |
|------|-----------|----------------|
| `rectangle.yaml` | Standard rectangle, 60x45 m | Training |
| `trapezoid.yaml` | Trapezoid, wider at entrance (front=48, rear=30, depth=44 m) | Training |
| `irregular_a.yaml` | Nine-sided irregular polygon (~80x50 m), diagonal top wall and bottom notch | OOD only |

Each layout YAML contains: `corners` (perimeter polygon), `bays` (15 bay definitions with positions, dimensions, `always_empty` flags), `spawn_transform` (ego start pose), `patrol_waypoints`, and `pedestrian_zones`. Consumed by `CARLAParkingEnv._load_floor_plan()`.

Lot origins are pre-set for the FlatPlane map. Use `make docker-inspect LAYOUT=<name>` to verify placement visually. If you move a lot, update `origin.x/y` and re-run `make generate-layouts`.

### `training/`

Training-specific configs:

- `tuning_config.yaml` -- Optuna hyperparameter tuning study settings and search space bounds. **NOT modified during tuning**. Defines where Optuna should search (e.g., `learning_rate: [1e-5, 2e-3]`, `n_steps: [1024, 2048, 4096]`). Consumed by `tune_hyperparams.py`. Edit to adjust tuning parameters (number of trials, timesteps per trial, random seed).
- `tuning_results/` -- Directory created after tuning completes. Contains `best_params.yaml` (standalone copy of best trial hyperparameters for reference).

### `maps/`

Cartographer `.pbstream` SLAM maps, split by LiDAR dimensionality:

```
maps/
  2d/          # Suite A (2D LiDAR) pbstreams
    rectangle.pbstream
    trapezoid.pbstream
    irregular_a.pbstream
  3d/          # Suite B/C (3D LiDAR) pbstreams
    rectangle.pbstream
    ...
```

Generated by `make docker-map LAYOUT=<name>`. The Makefile reads `sensor_suite` from `carla/env_config.yaml` to select `2d` or `3d` automatically. Do not create pbstreams manually.

## Hyperparameter Tuning Workflow

```
configs/training/tuning_config.yaml (search space bounds)
            ↓
      make docker-tune  (Optuna, 50 trials × 150k steps each)
            ↓
configs/train_config.yaml (best params written back)
            ↓
   make docker-train-loc  (uses tuned hyperparameters)
```

The search space bounds stay in `configs/training/tuning_config.yaml` (unchanged). Only the selected best values are written to `configs/train_config.yaml` (with `.bak` backup). To resume a paused tuning study, re-run `make docker-tune` — it reads from the SQLite database and continues from the last completed trial.

## Convention

- All consuming code uses `.get(key, default)` so configs are backwards-compatible.
- Units are commented inline in each YAML.
- New parameters must be added to the relevant YAML with sensible defaults before use in code.
- Structural constants (dimensions, thresholds) live in `uncertainty_rl/utils/constants.py`, not here.
